# Software Design & Architecture Roadmap: Fundamentals → Intermediate

> General knowledge for software developers, with software-design-specific context.

## Design Principles (Prerequisites)

- [ ] **Phase 1** — SOLID: SRP, OCP, LSP, ISP, DIP
- [ ] **Phase 2** — Simplicity: DRY, KISS, YAGNI, rule of three
- [ ] **Phase 3** — Coupling & cohesion: dependency direction, module strength
- [ ] **Phase 4** — Separation of concerns: layers, boundaries, responsibilities
- [ ] **Phase 5** — Composition over inheritance: reuse, flexibility

## OOP & Programming Paradigms

- [ ] **Phase 6** — OOP fundamentals: encapsulation, abstraction, polymorphism
- [ ] **Phase 7** — Design by contract: preconditions, postconditions, invariants
- [ ] **Phase 8** — Functional design: immutability, pure functions, option types
- [ ] **Phase 9** — Typing & modeling: type-driven design, constraints in types
- [ ] **Phase 10** — Refactoring basics: smells, transformations, safety

## Design Patterns

- [ ] **Phase 11** — Creational patterns: factory, builder, singleton, prototype
- [ ] **Phase 12** — Structural patterns: adapter, facade, decorator, proxy, composite
- [ ] **Phase 13** — Behavioral patterns: strategy, observer, command, template, state
- [ ] **Phase 14** — Concurrency patterns: worker, reactor, producer-consumer
- [ ] **Phase 15** — Anti-patterns: god object, spaghetti, golden hammer, cargo cult
- [ ] **Phase 16** — Pattern selection: contexts, costs, alternatives

## Architecture Styles

- [ ] **Phase 17** — Layered architecture: presentation, domain, data layers
- [ ] **Phase 18** — Hexagonal architecture: ports, adapters, core isolation
- [ ] **Phase 19** — Microservices: boundaries, communication, ownership
- [ ] **Phase 20** — Event-driven architecture: events, brokers, sagas
- [ ] **Phase 21** — Modular monolith: modules, seams, evolution paths

## Clean Architecture

- [ ] **Phase 22** — Clean layers: entities, use cases, interfaces, infrastructure
- [ ] **Phase 23** — Dependency rule: inward dependencies, abstraction
- [ ] **Phase 24** — Use cases: application logic, orchestration, DTOs
- [ ] **Phase 25** — Entities & domain models: business rules, invariants
- [ ] **Phase 26** — Adapters & boundaries: gateways, presenters, frameworks

## Domain-Driven Design

- [ ] **Phase 27** — Ubiquitous language: shared terminology, glossary
- [ ] **Phase 28** — Bounded contexts: context maps, relationships
- [ ] **Phase 29** — Aggregates: consistency boundaries, roots, invariants
- [ ] **Phase 30** — Value objects & entities: identity, equality, semantics
- [ ] **Phase 31** — Tactical patterns: repositories, domain services, factories

## Modularity & Code Structure

- [ ] **Phase 32** — Module boundaries: APIs, visibility, encapsulation
- [ ] **Phase 33** — Package design: dependency graphs, cycles, depth
- [ ] **Phase 34** — Dependency management: inversion, injection, composition roots
- [ ] **Phase 35** — Feature structure: vertical slices, folders, naming

## Documentation & Diagrams

- [ ] **Phase 36** — ADRs: decision context, options, consequences
- [ ] **Phase 37** — C4 model: context, container, component, code diagrams
- [ ] **Phase 38** — UML basics: class, sequence, component diagrams
- [ ] **Phase 39** — Design docs: goals, design, tradeoffs, reviews

## Practical Design Skills

- [ ] **Phase 40** — Legacy code: seams, characterization tests, incremental change
- [ ] **Phase 41** — Design reviews: critique, tradeoff analysis, consensus
- [ ] **Phase 42** — Spikes & experiments: validating design choices
- [ ] **Phase 43** — Technical debt: tracking, repayment, communication
- [ ] **Phase 44** — Decision making: options, risks, reversibility

## Career & Practice

- [ ] **Phase 45** — Case studies: real-world designs, tradeoff analysis
- [ ] **Phase 46** — Practice: kata, redesign exercises, open source
- [ ] **Phase 47** — Interview prep: design questions, whiteboarding

## Recommended Learning Path (priority order)

1. **Phase 1–5** — Design principles
2. **Phase 6–10** — Paradigms & modeling
3. **Phase 11–16** — Design patterns
4. **Phase 17–21** — Architecture styles
5. **Phase 22–26** — Clean architecture
6. **Phase 27–31** — Domain-driven design
7. **Phase 36–39** — Documentation & diagrams

> Focus on building real projects — employers hire mid-level engineers for clean, well-designed, maintainable code plus ownership of features end-to-end.
