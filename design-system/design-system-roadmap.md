# Design System Roadmap: Fundamentals → Intermediate

> General knowledge for frontend developers, with design-system-specific context.

## Design System Fundamentals (Prerequisites)

- [ ] **Phase 1** — What & why: definitions, value, cost-benefit
- [ ] **Phase 2** — Anatomy: tokens, components, patterns, guidelines
- [ ] **Phase 3** — Adoption models: centralized vs federated, hybrid
- [ ] **Phase 4** — Roles & governance: owners, contributors, reviewers

## Design Tokens

- [ ] **Phase 5** — Token types: color, typography, spacing, radius, motion
- [ ] **Phase 6** — Naming conventions: semantic vs primitive, hierarchy
- [ ] **Phase 7** — Semantic tokens: intent-based, themes, aliases
- [ ] **Phase 8** — Theming: light/dark, brand, contrast modes
- [ ] **Phase 9** — Platform delivery: web, iOS, Android formats
- [ ] **Phase 10** — Token pipelines: source of truth, generation, syncing

## Components

- [ ] **Phase 11** — Component anatomy: structure, slots, parts
- [ ] **Phase 12** — Variants & states: sizes, modes, hover, disabled
- [ ] **Phase 13** — Composition: compound components, slots API
- [ ] **Phase 14** — API design: props, defaults, extensibility
- [ ] **Phase 15** — Accessibility in components: roles, semantics, focus
- [ ] **Phase 16** — Component docs: props tables, examples, guidelines

## Foundations

- [ ] **Phase 17** — Color: palettes, contrast, usage rules
- [ ] **Phase 18** — Typography: scales, weights, usage, hierarchy
- [ ] **Phase 19** — Spacing: scales, 4/8px systems, density
- [ ] **Phase 20** — Iconography: icon sets, grids, sizing, semantics
- [ ] **Phase 21** — Motion: durations, easing, purpose, reduced motion

## Styling & Implementation

- [ ] **Phase 22** — CSS strategies: modules, CSS-in-JS, utility approaches
- [ ] **Phase 23** — CSS variables: tokens mapping, runtime theming
- [ ] **Phase 24** — Theming engines: context, data attributes, providers
- [ ] **Phase 25** — Responsive components: breakpoints, fluid design
- [ ] **Phase 26** — Performance: bundle size, tree shaking, style costs

## Documentation

- [ ] **Phase 27** — Docs sites: structure, navigation, search
- [ ] **Phase 28** — Usage guidelines: do/don't, best practices
- [ ] **Phase 29** — Examples: live demos, code snippets, playgrounds
- [ ] **Phase 30** — Versioning: changelogs, migration guides, semver

## Tooling & Workflow

- [ ] **Phase 31** — Figma libraries: components, styles, syncing
- [ ] **Phase 32** — Code generation: tokens to code, scaffolding
- [ ] **Phase 33** — Component testing: unit, visual regression, a11y tests
- [ ] **Phase 34** — CI integration: linting, builds, docs checks
- [ ] **Phase 35** — Distribution: npm packages, versioning, publishing

## Governance & Adoption

- [ ] **Phase 36** — Contribution process: requests, reviews, releases
- [ ] **Phase 37** — Reviews: design review, code review, standards
- [ ] **Phase 38** — Adoption tracking: usage metrics, migration status
- [ ] **Phase 39** — Evolution & deprecation: sunsetting, replacements
- [ ] **Phase 40** — Community: office hours, champions, training

## Accessibility & Quality

- [ ] **Phase 41** — WCAG in systems: criteria, conformance targets
- [ ] **Phase 42** — Keyboard & focus: order, traps, visible focus
- [ ] **Phase 43** — Contrast & type: AA/AAA, scaling, legibility
- [ ] **Phase 44** — Quality checks: audits, regressions, release gates

## Career & Strategy

- [ ] **Phase 45** — Measuring impact: adoption, consistency, velocity
- [ ] **Phase 46** — Case studies: before/after, business outcomes
- [ ] **Phase 47** — Roadmap: priorities, milestones, stakeholder buy-in

## Recommended Learning Path (priority order)

1. **Phase 1–4** — Fundamentals
2. **Phase 5–10** — Design tokens
3. **Phase 11–16** — Components
4. **Phase 17–21** — Foundations
5. **Phase 27–30** — Documentation
6. **Phase 36–40** — Governance & adoption
7. **Phase 41–44** — Accessibility & quality

> Focus on building real projects — employers hire mid-level design system devs for clean, consistent, well-tested systems plus ownership of design infrastructure end-to-end.
