# Technical Writer Roadmap: Fundamentals → Intermediate

> General knowledge for technical writers, with technical-writing-specific context.

## Writing Fundamentals (Prerequisites)

- [ ] **Phase 1** — Grammar & style: sentence structure, punctuation, clarity
- [ ] **Phase 2** — Plain language: simple words, active voice, conciseness
- [ ] **Phase 3** — Technical accuracy: precision, terminology, correctness
- [ ] **Phase 4** — Editing & revision: self-editing, peer review, consistency

## Documentation Types

- [ ] **Phase 5** — User guides: task-based writing, procedures, troubleshooting
- [ ] **Phase 6** — Tutorials: learning paths, prerequisites, exercises
- [ ] **Phase 7** — Reference docs: command, config, and data references
- [ ] **Phase 8** — Release notes & changelogs: scoping, tone, categorization
- [ ] **Phase 9** — Getting started: quickstarts, onboarding, installation

## Docs-as-Code

- [ ] **Phase 10** — Markdown: syntax, formatting, tables, links
- [ ] **Phase 11** — Git workflows: branches, pull requests, reviews
- [ ] **Phase 12** — Static site generators: docs sites, themes, navigation
- [ ] **Phase 13** — Docs CI/CD: linting, builds, previews, publishing
- [ ] **Phase 14** — Docs repositories: structure, ownership, maintenance
- [ ] **Phase 15** — Versioned docs: branches per release, version selectors

## Information Architecture

- [ ] **Phase 16** — Audience analysis: personas, skill levels, contexts
- [ ] **Phase 17** — Docs structure: hierarchy, navigation, information types
- [ ] **Phase 18** — Metadata: front matter, taxonomies, tagging
- [ ] **Phase 19** — Searchability: headings, keywords, discoverability

## API Documentation

- [ ] **Phase 20** — API fundamentals: endpoints, methods, parameters, responses
- [ ] **Phase 21** — Endpoint docs: request/response, errors, examples
- [ ] **Phase 22** — OpenAPI/Swagger: specs, generation, consistency
- [ ] **Phase 23** — SDK & library guides: setup, usage, patterns
- [ ] **Phase 24** — Code samples: accuracy, runnable examples, snippets
- [ ] **Phase 25** — API tutorials: onboarding flows, use cases

## Tools & Platforms

- [ ] **Phase 26** — Docs platforms: ReadMe, GitBook, Docusaurus, Mintlify
- [ ] **Phase 27** — Diagramming: Mermaid, flowchart, sequence diagrams
- [ ] **Phase 28** — Visual assets: screenshots, annotations, image workflows
- [ ] **Phase 29** — Content management: reuse, single-sourcing, snippets
- [ ] **Phase 30** — Publishing workflows: review gates, staging, analytics

## UX Writing & Content

- [ ] **Phase 31** — Microcopy: buttons, labels, tooltips, empty states
- [ ] **Phase 32** — Error messages: actionable, humane, consistent
- [ ] **Phase 33** — Onboarding content: first-run, tutorials, walkthroughs
- [ ] **Phase 34** — Tone of voice: brand voice, style application

## Research & Subject Mastery

- [ ] **Phase 35** — Learning new technology: docs, code reading, experiments
- [ ] **Phase 36** — SME interviews: preparation, extraction, follow-ups
- [ ] **Phase 37** — Testing docs: following steps, validating examples
- [ ] **Phase 38** — Docs analytics: search queries, page views, feedback

## Career & Collaboration

- [ ] **Phase 39** — Working with engineers & product: planning, reviews
- [ ] **Phase 40** — Docs metrics: coverage, time-to-answer, adoption
- [ ] **Phase 41** — Style guides: creation, maintenance, enforcement
- [ ] **Phase 42** — Localization: translation workflows, terminology, i18n
- [ ] **Phase 43** — Community docs: contributions, reviews, governance

## Professional Development

- [ ] **Phase 44** — Portfolio: samples, case studies, before/after
- [ ] **Phase 45** — Freelancing: contracts, scoping, client relations
- [ ] **Phase 46** — AI-assisted writing: prompt workflows, verification
- [ ] **Phase 47** — Career paths: specialization, management, consultancy

## Recommended Learning Path (priority order)

1. **Phase 1–4** — Writing fundamentals
2. **Phase 5–9** — Documentation types
3. **Phase 10–15** — Docs-as-code
4. **Phase 20–25** — API documentation
5. **Phase 16–19** — Information architecture
6. **Phase 31–34** — UX writing
7. **Phase 44–47** — Professional development

> Focus on building real projects — employers hire mid-level technical writers for clean, accurate, well-structured docs plus ownership of documentation end-to-end.
