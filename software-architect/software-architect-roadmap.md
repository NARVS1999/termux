# Software Architect Roadmap: Fundamentals → Intermediate

> General knowledge for software developers, with software-architecture-specific context.

## Foundations (Prerequisites)

- [ ] **Phase 1** — OOP & SOLID: encapsulation, inheritance, polymorphism, SRP, OCP
- [ ] **Phase 2** — Design patterns: creational, structural, behavioral patterns overview
- [ ] **Phase 3** — Modeling & diagrams: UML, sequence diagrams, component diagrams
- [ ] **Phase 4** — Requirements analysis: functional vs non-functional, constraints, stories

## Architecture Principles

- [ ] **Phase 5** — Quality attributes: performance, scalability, availability, security
- [ ] **Phase 6** — Modularity: separation of concerns, layers, boundaries
- [ ] **Phase 7** — Coupling & cohesion: loose coupling, high cohesion, dependency direction
- [ ] **Phase 8** — Simplicity: YAGNI, KISS, DRY, avoiding over-engineering
- [ ] **Phase 9** — Tradeoffs: decision framing, cost of complexity, reversibility

## Architecture Styles

- [ ] **Phase 10** — Layered & n-tier: presentation, domain, data layers
- [ ] **Phase 11** — Monolithic vs modular: decomposition, modules, future extraction
- [ ] **Phase 12** — Microservices: boundaries, communication, data ownership
- [ ] **Phase 13** — Event-driven: events, brokers, choreography vs orchestration
- [ ] **Phase 14** — Serverless: functions, managed services, cold starts
- [ ] **Phase 15** — Hybrid & evolutionary: strangler pattern, incremental migration

## Design Patterns & Practices

- [ ] **Phase 16** — Creational patterns: factory, builder, singleton, DI containers
- [ ] **Phase 17** — Structural patterns: adapter, facade, decorator, proxy
- [ ] **Phase 18** — Behavioral patterns: strategy, observer, template, command
- [ ] **Phase 19** — DDD basics: bounded contexts, aggregates, ubiquitous language
- [ ] **Phase 20** — CQRS & event sourcing: reads vs writes, event stores, projections

## Distributed Systems

- [ ] **Phase 21** — CAP theorem: consistency, availability, partition tolerance
- [ ] **Phase 22** — Consistency models: strong, eventual, linearizability, CRDTs
- [ ] **Phase 23** — Messaging: queues, topics, brokers, ordering, delivery semantics
- [ ] **Phase 24** — Caching strategies: cache-aside, write-through, TTLs, invalidation
- [ ] **Phase 25** — Idempotency & retries: keys, exponential backoff, at-least-once
- [ ] **Phase 26** — Distributed transactions: sagas, two-phase commit, outbox pattern

## Data Architecture

- [ ] **Phase 27** — Database selection: relational vs NoSQL, workloads, tradeoffs
- [ ] **Phase 28** — Data modeling at scale: normalization, star schemas, partitioning
- [ ] **Phase 29** — Data flows: ETL/ELT, streams, data lakes, warehouses
- [ ] **Phase 30** — Analytics & reporting: cubes, OLAP, BI layers
- [ ] **Phase 31** — Data governance: ownership, contracts, quality, privacy

## Security Architecture

- [ ] **Phase 32** — Threat modeling: STRIDE, attack surfaces, risk decisions
- [ ] **Phase 33** — Secure design: least privilege, defense in depth, zero trust
- [ ] **Phase 34** — Identity & access: SSO, OAuth/OIDC, token strategies
- [ ] **Phase 35** — Compliance: audit, retention, encryption, data residency

## Cloud & Infrastructure Architecture

- [ ] **Phase 36** — Cloud patterns: regions, zones, managed services, multi-cloud
- [ ] **Phase 37** — Scalability: horizontal scaling, load balancing, autoscaling
- [ ] **Phase 38** — Resilience: redundancy, failover, chaos engineering
- [ ] **Phase 39** — Cost architecture: pricing models, waste reduction, budgets

## Documentation & Communication

- [ ] **Phase 40** — ADRs: architecture decision records, context, consequences
- [ ] **Phase 41** — Architecture diagrams: C4 model, context, container, component
- [ ] **Phase 42** — Presentations: tailoring to audiences, visual storytelling
- [ ] **Phase 43** — Stakeholders: product, ops, security alignment

## Leadership & Career

- [ ] **Phase 44** — Technical leadership: guiding teams, review processes, standards
- [ ] **Phase 45** — Estimation & planning: sizing, sequencing, risk communication
- [ ] **Phase 46** — Mentoring: growing senior engineers, knowledge sharing
- [ ] **Phase 47** — Interview prep: architecture scenarios, whiteboarding, tradeoff talks

## Recommended Learning Path (priority order)

1. **Phase 1–4** — Foundations
2. **Phase 5–9** — Architecture principles
3. **Phase 10–15** — Architecture styles
4. **Phase 21–26** — Distributed systems
5. **Phase 27–31** — Data architecture
6. **Phase 40–43** — Documentation & communication
7. **Phase 44–47** — Leadership & career

> Focus on building real projects — employers hire mid-level software architects for clean, scalable, well-documented systems plus ownership of design end-to-end.
