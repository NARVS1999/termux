# Next.js Developer Roadmap: Fundamentals → Intermediate

> General knowledge for frontend developers, with Next.js-specific context.

## React & Web Prerequisites (Prerequisites)

- [ ] **Phase 1** — React basics: components, props, state, events
- [ ] **Phase 2** — React hooks: useState, useEffect, custom hooks
- [ ] **Phase 3** — JavaScript & TypeScript: types, async, modules
- [ ] **Phase 4** — Web fundamentals: HTTP, rendering, browser APIs
- [ ] **Phase 5** — npm & tooling: packages, scripts, build tools

## Next.js Fundamentals

- [ ] **Phase 6** — What is Next.js: features, SSR/SSG, full-stack framework
- [ ] **Phase 7** — create-next-app: setup, templates, configuration
- [ ] **Phase 8** — Project structure: folders, files, conventions
- [ ] **Phase 9** — App Router vs Pages: models, migrations, tradeoffs
- [ ] **Phase 10** — Dev experience: hot reload, dev tools, debugging

## Routing

- [ ] **Phase 11** — File-based routing: routes, files, conventions
- [ ] **Phase 12** — Dynamic routes: params, catch-all, generating paths
- [ ] **Phase 13** — Layouts: nested layouts, templates, route groups
- [ ] **Phase 14** — Loading & error states: loading files, error boundaries
- [ ] **Phase 15** — Linking & navigation: Link, useRouter, prefetching

## Rendering

- [ ] **Phase 16** — Server vs client components: boundaries, directives
- [ ] **Phase 17** — Server-side rendering: dynamic data, cookies, headers
- [ ] **Phase 18** — Static generation: prerendering, static params
- [ ] **Phase 19** — Streaming & suspense: partial loading, fallbacks
- [ ] **Phase 20** — Caching: fetch cache, revalidation, cache layers

## Data Fetching

- [ ] **Phase 21** — Server data fetching: async components, fetch patterns
- [ ] **Phase 22** — Server Actions: mutations, forms, progressive enhancement
- [ ] **Phase 23** — Client fetching: SWR, TanStack Query, effects
- [ ] **Phase 24** — Mutations & invalidation: revalidation, optimistic updates
- [ ] **Phase 25** — Data patterns: caching strategies, deduplication

## Styling & UI

- [ ] **Phase 26** — CSS Modules: scoped styles, composition
- [ ] **Phase 27** — Tailwind CSS: utility classes, config, responsive
- [ ] **Phase 28** — Global styles & themes: variables, dark mode
- [ ] **Phase 29** — Fonts & images: next/font, next/image, optimization

## Forms & Mutations

- [ ] **Phase 30** — Forms with Server Actions: actions, pending states
- [ ] **Phase 31** — Validation: client and server validation, errors
- [ ] **Phase 32** — Optimistic updates: rollback, conflict handling
- [ ] **Phase 33** — Form error handling: field errors, global errors

## Auth & Middleware

- [ ] **Phase 34** — Authentication: NextAuth, credentials, providers
- [ ] **Phase 35** — Middleware: matchers, redirects, protection
- [ ] **Phase 36** — Protected routes: sessions, role checks
- [ ] **Phase 37** — Security headers: CSP, headers config, CSRF

## APIs & Integrations

- [ ] **Phase 38** — Route handlers: requests, responses, streaming
- [ ] **Phase 39** — Environment & config: env vars, validation, secrets
- [ ] **Phase 40** — Third-party services: databases, CMS, payments

## Performance & SEO

- [ ] **Phase 41** — Core Web Vitals: LCP, INP, CLS optimization
- [ ] **Phase 42** — Image optimization: next/image, formats, loading
- [ ] **Phase 43** — Metadata & SEO: metadata API, sitemaps, OG images
- [ ] **Phase 44** — Bundle & caching strategies: code splitting, cache layers

## Deployment & Production

- [ ] **Phase 45** — Deployment: Vercel, self-hosting, static exports
- [ ] **Phase 46** — CI/CD & environments: pipelines, staging, config
- [ ] **Phase 47** — Monitoring & analytics: logs, errors, performance data

## Recommended Learning Path (priority order)

1. **Phase 1–5** — React prerequisites
2. **Phase 6–10** — Next.js fundamentals
3. **Phase 11–15** — Routing
4. **Phase 16–20** — Rendering
5. **Phase 21–25** — Data fetching
6. **Phase 34–37** — Auth & middleware
7. **Phase 41–44** — Performance & SEO

> Focus on building real projects — employers hire mid-level Next.js devs for clean, performant, well-tested code plus ownership of features end-to-end.
